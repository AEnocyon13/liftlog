# スプレッドシート スキーマ

`setupSpreadsheet()` を実行すると、全員共通の3シート（Users / Menus / Settings）がヘッダ付きで作られる。
**実績シートはユーザーごと**で、アプリで苗字を登録したときに自動生成される。

```
Users        … 登録ユーザーと個人設定（全員共通）
Menus        … 種目マスター（全員共通・48種目）
Settings     … 既定値（全員共通）
Logs_tanaka      … tanaka の実績（1行 = 1セット）
Sessions_tanaka  … tanaka のワークアウト単位のサマリ
Logs_suzuki      … suzuki の実績
Sessions_suzuki  … suzuki のサマリ
```

**1行目のヘッダ名がプログラムの参照キー**なので、列の並び替えは可能だが、名前の変更・削除は不可。

---

## Users — 登録ユーザーと個人設定

苗字（小文字ローマ字）1つでログインする。パスワードは無く、APIキーを知っているクライアントだけが
到達できる前提の簡易識別。新しい苗字でログインすると、アプリ上で確認したうえでこのシートに追記され、
同時に `Logs_<姓>` と `Sessions_<姓>` が作られる。

| 列 | 型 | 説明 |
|---|---|---|
| `surname` | 文字列 | 苗字。`^[a-z]{1,20}$`（小文字ローマ字のみ）。シート名の接尾辞になる |
| `displayName` | 文字列 | 氏名。画面に表示される名前（日本語可・40文字以内） |
| `pinHash` | 文字列 | 4桁PINのハッシュ（SHA-256 hex）。**PIN そのものは保存しない** |
| `pinSalt` | 文字列 | ハッシュに使うユーザーごとのソルト |
| `createdAt` | 文字列 ISO8601 | 登録日時 |
| `lastLoginAt` | 文字列 ISO8601 | 最終ログイン日時 |
| `monthlyTargetWorkouts` | 数値 | 月間目標ワークアウト回数（ダッシュボードの達成率の分母） |
| `monthlyTargetVolume` | 数値 | 月間目標総ボリューム(kg)。0 で非表示 |
| `weightIncrement` | 数値 | 前回比で自動的に足す重量(kg)。既定 2.5 |
| `restMinutes` | 数値 | 休憩タイマーの既定値(分)。アプリ側で変更すると自動で書き戻される |
| `memo` | 文字列 | 任意のメモ |

> 苗字を手で書き換えると、対応する `Logs_<姓>` シートと結びつかなくなる。
> 変更する場合はシート名も合わせてリネームすること。

### PINを忘れたとき

該当行の **`pinHash` と `pinSalt` のセルを空にする**と、その人は次のログインで
「PINを設定してください」画面が出て、好きなPINを決め直せる。記録は消えない。

### 覗き見（閲覧のみ）について

ログイン画面で PIN を入れずに「覗き見する」を選ぶと、その人の記録を閲覧だけできる。
覗き見ではトークンが発行されないため、ワークアウトの開始・記録・設定変更は
**サーバー側で拒否される**（UI を迂回して API を直接叩いても書き込めない）。

列を後から増やしても壊れないよう、Users シートの読み書きは
常に「シートの実際のヘッダ」を見て行っている。列の並び順を変えても動作する。

## Logs_&lt;姓&gt; — 実績（1行 = 1セット）

ワークアウト終了時に、記録された全セットが追記される。

| 列 | 型 | 説明 |
|---|---|---|
| `logId` | 文字列 | セット単位のユニークID |
| `sessionId` | 文字列 | どのワークアウトに属するか（Sessions_&lt;姓&gt; と紐づく） |
| `date` | 文字列 `yyyy-MM-dd` | 実施日。タイムゾーンずれ防止のため書式は「書式なしテキスト」 |
| `part` | 文字列 | 部位 |
| `menu` | 文字列 | 種目名 |
| `setNo` | 数値 | セット番号（ウォームアップは 0） |
| `weight` | 数値 | 重量 kg |
| `reps` | 数値 | レップ数 |
| `rpe` | 数値 / 空 | 主観的きつさ 6〜10。任意。記録は残るが重量提案には使われない |
| `isWarmup` | 真偽 | TRUE のセットは引き継ぎ・ボリューム集計から除外 |
| `volume` | 数値 | `weight × reps`（ウォームアップは 0） |
| `est1RM` | 数値 | Epley式の推定1RM `weight × (1 + reps / 30)` |
| `memo` | 文字列 | セット単位のメモ |
| `createdAt` | 文字列 ISO8601 | 書き込み時刻 |

## Sessions_&lt;姓&gt; — ワークアウト単位のサマリ

開始時に `endTime` 空の行が追記され、終了時に同じ行が更新される。

| 列 | 型 | 説明 |
|---|---|---|
| `sessionId` | 文字列 | ユニークID |
| `date` | 文字列 `yyyy-MM-dd` | 実施日 |
| `startTime` / `endTime` | 文字列 ISO8601 | 開始 / 終了時刻（`endTime` が空 = 進行中） |
| `durationMin` | 数値 | 所要分 |
| `parts` / `menus` | 文字列 | 実施した部位・種目（` / ` 区切り） |
| `totalSets` | 数値 | 作業セット数 |
| `totalVolume` | 数値 | 総ボリューム kg |
| `restMinutes` | 数値 | そのワークアウトで使った休憩時間(分) |
| `memo` | 文字列 | ワークアウトのメモ |
| `createdAt` | 文字列 ISO8601 | 作成時刻 |

## Menus — 種目マスター（全員共通）

初期値は Notion「筋トre」の 種目｜Exercises データベースから取り込んだ **48種目**（[notion-guide-source.md](notion-guide-source.md)）。
部位は 胸 / 背中 / 脚 / 肩 / 腕 / 腹 の6つ。**ここを編集して種目を増減する。**

| 列 | 型 | 既定 | 説明 |
|---|---|---|---|
| `part` | 文字列 | — | 部位。この単位で選択チップが並ぶ。並び順はシートの出現順 |
| `menu` | 文字列 | — | 種目名。解説ドキュメントの見出し2と揃える |
| `equipment` | 文字列 | — | バーベル / ダンベル / マシン / ケーブル / 自重（表示のみ） |
| `repMin` | 数値 | 8 | 履歴が無い種目で表示する目標レップ下限 |
| `repMax` | 数値 | 12 | 同上・上限 |
| `defaultSets` | 数値 | 3 | 履歴が無い種目の初期セット数 |
| `order` | 数値 | 999 | 部位内の表示順 |
| `active` | 真偽 | TRUE | FALSE にすると選択肢から消える（過去ログは残る） |

> 履歴がある種目では `repMin` / `repMax` / `defaultSets` は使われない。
> セット数もレップ数も前回の実績から引き継がれるため。

## Settings — 全員共通の既定値（key / value / description）

| key | 既定 | 説明 |
|---|---|---|
| `defaultRepMin` | 8 | 履歴が無い種目の目標レップ下限 |
| `defaultRepMax` | 12 | 同上・上限 |
| `defaultWeightIncrement` | 2.5 | 増量幅の既定（ユーザー登録時に Users へコピーされる） |
| `defaultRestMinutes` | 3 | 休憩タイマーの既定（同上） |
| `defaultMonthlyTarget` | 12 | 月間目標回数の既定（同上） |
| `timezone` | Asia/Tokyo | 日付計算に使うタイムゾーン |

個人設定（Users シート）が存在する場合はそちらが優先される。

## v1 からの移行

ユーザー分割前の `Logs` / `Sessions` シートがある場合は、GASエディタで次を実行すると移せる。

```
migrateLegacyData('yamada')
```

指定した苗字のユーザーを（未登録なら）作成し、旧シートの全行を `Logs_yamada` / `Sessions_yamada` へ
コピーしたうえで、旧シートを `Logs_legacy` / `Sessions_legacy` にリネームして残す。

## 手作業で過去データを入れる場合

`Logs_<姓>` に直接行を足せば、提案も集計もそのまま効く。最低限必要なのは
`sessionId` / `date` / `part` / `menu` / `setNo` / `weight` / `reps` の7列。
`sessionId` は同じワークアウトの行で同一の任意文字列にすること（例：`20260901-chest`）。

```
volume  = weight * reps
est1RM  = ROUND(weight * (1 + reps / 30), 1)
```
