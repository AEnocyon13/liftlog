# スプレッドシート スキーマ

`setupSpreadsheet()` を実行すると、以下4シートがヘッダ付きで自動生成される。
**1行目のヘッダ名がプログラムの参照キー**なので、列の並び替えは可能だが、名前の変更・削除は不可。

---

## Logs — 実績（1行 = 1セット）

ワークアウト終了時に、記録された全セットが追記される。

| 列 | 型 | 説明 |
|---|---|---|
| `logId` | 文字列 | セット単位のユニークID |
| `sessionId` | 文字列 | どのワークアウトに属するか（Sessions と紐づく） |
| `date` | 文字列 `yyyy-MM-dd` | 実施日。タイムゾーンずれ防止のため書式は「書式なしテキスト」 |
| `part` | 文字列 | 部位 |
| `menu` | 文字列 | 種目名 |
| `setNo` | 数値 | セット番号（ウォームアップは 0） |
| `weight` | 数値 | 重量 kg |
| `reps` | 数値 | レップ数 |
| `rpe` | 数値 / 空 | 主観的きつさ 6〜10。空でも動くが、記録すると提案精度が上がる |
| `isWarmup` | 真偽 | TRUE のセットは提案計算・ボリューム集計から除外 |
| `volume` | 数値 | `weight × reps`（ウォームアップは 0） |
| `est1RM` | 数値 | Epley式の推定1RM `weight × (1 + reps / 30)` |
| `memo` | 文字列 | セット単位のメモ |
| `createdAt` | 文字列 ISO8601 | 書き込み時刻 |

## Sessions — ワークアウト単位のサマリ

開始時に `endTime` 空の行が追記され、終了時に同じ行が更新される。
`endTime` が空の行は「進行中」とみなされる。

| 列 | 型 | 説明 |
|---|---|---|
| `sessionId` | 文字列 | ユニークID |
| `date` | 文字列 `yyyy-MM-dd` | 実施日 |
| `startTime` | 文字列 ISO8601 | 開始時刻 |
| `endTime` | 文字列 ISO8601 | 終了時刻（空 = 進行中） |
| `durationMin` | 数値 | 所要分 |
| `parts` | 文字列 | 実施した部位（` / ` 区切り） |
| `menus` | 文字列 | 実施した種目（` / ` 区切り） |
| `totalSets` | 数値 | 作業セット数 |
| `totalVolume` | 数値 | 総ボリューム kg |
| `condition` | 文字列 | 体調メモ（任意） |
| `memo` | 文字列 | ワークアウトのメモ |
| `createdAt` | 文字列 ISO8601 | 作成時刻 |

## Menus — 種目マスター

アプリの選択肢と、種目ごとの提案パラメータ。**ここを編集して種目を増やす**。

| 列 | 型 | 既定 | 説明 |
|---|---|---|---|
| `part` | 文字列 | — | 部位。この単位で選択チップが並ぶ |
| `menu` | 文字列 | — | 種目名。解説ドキュメントの見出し2と揃える |
| `equipment` | 文字列 | — | バーベル / ダンベル / マシン / ケーブル など（表示のみ） |
| `repMin` | 数値 | 8 | 目標レップ下限。これを全セット下回るとディロード判定に進む |
| `repMax` | 数値 | 12 | 目標レップ上限。全セット到達で増量する |
| `baseIncrement` | 数値 | 2.5 | 増量時の基準増加量 kg。RPE係数を掛けて使う |
| `weightStep` | 数値 | 2.5 | 実際に扱える最小刻み kg（プレート/マシンのピッチ）。提案値はこの倍数に丸められる |
| `defaultSets` | 数値 | 3 | 既定のセット数 |
| `order` | 数値 | 999 | 部位内の表示順 |
| `active` | 真偽 | TRUE | FALSE にすると選択肢から消える（過去ログは残る） |

**設定例**

| 種目 | repMin/Max | baseIncrement | weightStep | 意図 |
|---|---|---|---|---|
| バーベルスクワット | 8 / 12 | 5 | 2.5 | 下半身の大種目は大きく伸ばす |
| ベンチプレス | 8 / 12 | 2.5 | 2.5 | 上半身のコンパウンド |
| サイドレイズ | 12 / 15 | 1 | 1 | 単関節・高レップ。1kgダンベル刻み |
| レッグプレス | 10 / 15 | 10 | 5 | プレート単位が大きいマシン |

## Settings — 設定（key / value / description）

アプリの設定画面から編集できる。シートを直接編集してもよい。

| key | 既定 | 説明 |
|---|---|---|
| `monthlyTargetWorkouts` | 12 | 月間目標ワークアウト回数（ダッシュボードの達成率の分母） |
| `monthlyTargetVolume` | 0 | 月間目標総ボリューム kg。0 で非表示 |
| `deloadRate` | 0.10 | 連続未達時に落とす割合 |
| `deloadAfterFails` | 2 | 何回連続で下限レップ未達ならディロードするか |
| `defaultRepMin` | 8 | Menus に指定が無い場合の下限 |
| `defaultRepMax` | 12 | Menus に指定が無い場合の上限 |
| `defaultWeightStep` | 2.5 | Menus に指定が無い場合の刻み |
| `rpeEasyThreshold` | 7.0 | これ以下のRPEなら増加幅 ×1.5 |
| `rpeNormalThreshold` | 8.5 | これ以下のRPEなら増加幅 ×1.0 |
| `rpeHardThreshold` | 9.5 | これ以下のRPEなら増加幅 ×0.5 / 超過は据え置き |
| `timezone` | Asia/Tokyo | 日付計算に使うタイムゾーン |

## 手作業で過去データを移行する場合

`Logs` に直接行を足せば、提案アルゴリズムも集計もそのまま効く。最低限必要なのは
`sessionId` / `date` / `part` / `menu` / `setNo` / `weight` / `reps` の7列。
`sessionId` は同じワークアウトの行で同一の任意文字列にすること（例：`20260901-chest`）。
`volume` と `est1RM` は空でも提案には影響しないが、ダッシュボードの集計には使われるため、
埋めておくか、次の式を貼るとよい。

```
volume  = weight * reps
est1RM  = ROUND(weight * (1 + reps / 30), 1)
```
