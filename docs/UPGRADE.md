# 今やることリスト（v1 → v2 更新手順）

フロントエンド（アプリ画面）は更新済みですが、**Google Apps Script 側がまだ v1 のまま**です。
そのため苗字を入れて「はじめる」を押すと `未知のaction: login` になります。

このページの手順を上から順に行えば直ります。所要 10 分ほどです。

---

## 0. 作り直しは必要？

**結論：スプレッドシートもドキュメントも、作り直す必要はありません。**
ID も URL も API キーもそのまま使えます。中身の一部だけを入れ替えます。

| 対象 | 作り直し | 何をするか |
|---|:---:|---|
| スプレッドシート本体 | **不要** | 同じファイルを使い続ける（ID変更なし） |
| Googleドキュメント本体 | **不要** | 同じファイルを使い続ける（ID変更なし） |
| GASプロジェクト | **不要** | 同じプロジェクトにコードを貼り替えるだけ |
| ウェブアプリURL / APIキー | **不要** | 変わりません。アプリの設定もそのままでOK |
| `Menus` シートの中身 | **必要** | 列構成が変わったため作り直し（手順3が自動でやります） |
| `Settings` シートの中身 | 一部 | v2 で増えたキーを**追記**するだけ。設定した値はそのまま残ります |
| `Logs` / `Sessions` の記録 | 不要 | ユーザー別シートへ**移動**します。消えません |
| ドキュメントの解説本文 | 任意 | Notion の46種目に入れ替えたい場合のみ（手順6） |

> **なぜ Menus を作り直すのか**
> v2 で `baseIncrement` と `weightStep` の2列が不要になりました。1行目のヘッダが古いまま
> データだけ入れ替えると列がずれて壊れるため、シートごと作り直します。
> 旧シートは消さずに `Menus_v1backup_YYYYMMDD` という名前で残ります。

## 1. GASエディタにコードを貼り替える

[script.google.com](https://script.google.com/) で「LiftLog API」プロジェクトを開きます。

`backend/` の**11ファイルすべて**を、同じ名前で貼り替えてください。
**`Auth.gs` / `Users.gs` / `SeedData.gs` は v2 で新しく増えたファイル**なので、左の「ファイル」＋ボタンから
新規作成（種類は「スクリプト」）します。

```
appsscript.json   ← マニフェスト（歯車 → 「appsscript.json をエディタで表示する」にチェック）
Code.gs
Config.gs
Auth.gs         ★新規（PIN認証・トークン）
Users.gs        ★新規
SheetRepo.gs
DocRepo.gs
Progression.gs
Dashboard.gs
SeedData.gs     ★新規
Setup.gs
```

### 確認

- [ ] 左のファイル一覧がちょうど上の11個になっている
- [ ] `Code.gs` の上のほうに `login:` という行がある（無ければ貼り替えが効いていません）
- [ ] **古いファイルが残っていない**

> ⚠ 新しいコードを別名のファイルで追加して古い `Code.gs` を残すと、`doGet` などが二重定義になり、
> 古いほうが優先されて同じエラーが続きます。余分なファイルは削除してください。

保存（Cmd/Ctrl + S）します。

---

## 2. 保存されているか確かめる

エディタ上部の関数プルダウンに **`upgradeToV2`** が出てくれば、貼り替えは成功しています。
出てこない場合は保存されていないので、手順1をやり直してください。

---

## 3. 移行を実行する

関数プルダウンから **`upgradeToV2`** を選び、▶ 実行します。

このとき、**引数として自分の苗字を渡す必要があります。** エディタでは関数に引数を渡せないので、
`Setup.gs` の一番下に次の1行を足して、そちらを実行してください（実行後は消して構いません）。

```javascript
function runUpgrade() {
  upgradeToV2('yamada');   // ← 既存の記録の持ち主の苗字。小文字ローマ字のみ
}
```

関数プルダウンで `runUpgrade` を選び ▶ 実行します。

この1回で次がすべて行われます。

1. `Menus` を作り直す（旧シートは `Menus_v1backup_日付` にリネームして保全）
2. 種目46件を投入
3. `Settings` に v2 で増えたキーを追記（既存の値は書き換えません）
4. `Users` シートを作成し、増えた列（`displayName` / `pinHash` / `pinSalt`）を追記
5. 旧 `Logs` / `Sessions` の記録を `Logs_yamada` / `Sessions_yamada` へ移し、
   旧シートを `Logs_legacy` / `Sessions_legacy` にリネーム

**何度実行しても安全です。** 2回目以降は「列構成は最新（そのまま）」と表示され、
種目やユーザーが二重に増えることはありません。

### 確認

実行ログ（下部に自動で開きます）に、こんな内容が出れば成功です。

```
Menus: 旧シートを Menus_v1backup_20260925 にリネームして作り直し
種目: 46件
Settings: キーを追加 → defaultRepMin, defaultRepMax, defaultWeightIncrement, defaultRestMinutes, defaultMonthlyTarget, timezone
Settings: v2 では使わない行が残っています（消して構いません） → monthlyTargetWorkouts, deloadRate, rpeEasyThreshold
Users: 列を追加 → displayName, pinHash, pinSalt
旧データの移行 → Logs: 120行 / Sessions: 14行
登録ユーザー: ["yamada"]
PIN未設定: yamada → 次回ログイン時にアプリ上で設定できます

完了しました。次は GASエディタの「デプロイ」→…
```

最後の2行に出る `deloadRate` などは v1 で使っていた設定です。**消しても残しても動作に影響はありません。**

スプレッドシートを開いて、タブがこうなっていることも確認してください。

```
Users  Menus  Settings  Logs_yamada  Sessions_yamada
Menus_v1backup_…  Logs_legacy  Sessions_legacy
```

> 問題なく動くのを確認できたら、`Menus_v1backup_…` と `*_legacy` のタブは削除して構いません。
> 不安な間は残しておいて大丈夫です（アプリは参照しません）。

---

## 4. 再デプロイする（ここが一番忘れやすいです）

**コードを保存しただけでは、ウェブアプリは古いままです。** `/exec` はデプロイ済みバージョンを返すためです。

1. 右上「**デプロイ**」→「**デプロイを管理**」
2. 一覧にある既存デプロイの **鉛筆アイコン**（✏️）をクリック
3. 「バージョン」のプルダウンを「**新バージョン**」に変更
4. 「**デプロイ**」をクリック

> ⚠「新しいデプロイ」を選ぶと**別のURL**が発行され、アプリの設定を入れ直すことになります。
> 必ず「デプロイを管理」→ 鉛筆 から行ってください。URLは変わりません。

---

## 5. 動いているか確かめる

ブラウザのアドレスバーに次を入力して開きます（`{ }` は自分の値に置き換え）。

```
{ウェブアプリURL}?action=listUsers&key={APIキー}
```

| 表示された内容 | 意味 |
|---|---|
| `{"ok":true,"data":{"users":["yamada"]}}` | ✅ 成功。手順6へ |
| `{"ok":false,...UNKNOWN_ACTION...}` | ❌ 古いコードのまま。手順4の再デプロイが未完了 |
| `{"ok":false,...UNAUTHORIZED...}` | APIキーが違います |

成功したら [アプリ](https://aenocyon13.github.io/liftlog/) を開き直して、苗字を入れてログインしてください。

**既に登録済みの人は、初回だけ「PINを設定してください」と表示されます。**
氏名（任意）と4桁PINを決めれば、それ以降は PIN でログインできます。記録はそのまま残ります。
他の人の記録を見たいときは、その人の苗字を入れて「覗き見する（閲覧のみ）」を選んでください。

---

## 6. 種目の解説を入れ替える（任意）

Googleドキュメントに v1 の雛形（胸・背中の2種目だけ）が入っている場合、
Notion から取り込んだ46種目に入れ替えられます。**ドキュメント自体は作り直しません。**

1. Googleドキュメントを開く
2. **本文を全選択して削除**（Cmd/Ctrl + A → Delete）。空にしないと書き込みがスキップされます
3. GASエディタで **`seedGuideDoc`** を ▶ 実行
4. ログに `解説を書き込みました（46種目中 15件に本文あり）` と出れば成功
5. アプリの 設定 → 「解説ドキュメントを再読込」を押す

> 自分で書き足した解説がすでにある場合は、この手順を飛ばしてください。
> 種目を個別に足したいときは、ドキュメントに「見出し2 = 種目名」で追記すれば反映されます
> （書式は [DOC_FORMAT.md](DOC_FORMAT.md)）。

## つまずいたときは

| 症状 | 原因と対処 |
|---|---|
| `未知のaction: login` | 手順4の再デプロイが済んでいない。または手順1で `Code.gs` が古いまま |
| 関数一覧に `upgradeToV2` が無い | `Setup.gs` の貼り替えが保存されていない |
| `SeedData is not defined` | `SeedData.gs` を作成していない |
| `権限が不十分です … auth/documents` | `appsscript.json` が古い（`documents.readonly` のまま）。貼り替えて実行し直すと承認画面が出ます |
| 種目が0件のまま | `Menus` シートが空。`upgradeToV2` の実行ログを確認してください |
| ログインできるが記録が空 | 旧データの移行時に渡した苗字と、ログインに使った苗字が違う可能性があります |
| 途中で失敗した | `upgradeToV2` は何度実行しても安全です。原因を直してもう一度実行してください |
| 部位が「胸トレ」ではなく「胸」になっている | v2 の仕様です。`Menus` シートの `part` 列で好きな名前に変えられます |
| `verifyPin_ is not defined` などのエラー | `Auth.gs` を作成していません |
| PINを忘れた | Users シートで該当行の `pinHash` / `pinSalt` を空にすると、次回ログインで再設定できます |

---

## この先の通常運用

一度移行してしまえば、次からは次のときだけ GAS を触ります。

- **種目を足す/減らす** … `Menus` シートを直接編集 → アプリの 設定 → 「メニュー・設定を再読込」
- **解説を書く** … Googleドキュメントを編集 → アプリの 設定 → 「解説ドキュメントを再読込」
- **人を増やす** … アプリのログイン画面で新しい苗字を入れるだけ（シートは自動で作られます）
- **コードを直した** … 貼り替え → **必ず「デプロイを管理」から新バージョンで再デプロイ**
