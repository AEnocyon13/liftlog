# Google カレンダー連携の設定

ワークアウトを終了すると、こんな予定が自動で作られます。

```
筋トレ（胸・背中）           19:02 - 20:07

ベンチプレス　82.5kg × 10/9/8
ラットプルダウン　62.5kg/62.5kg/55kg × 12/12/10

合計 6セット・4,278kg・65分
メモ: 睡眠不足だが調子は良い

LiftLog で記録
```

書き込み先のカレンダーは、連携するときに**一覧から選びます**（IDを控える必要はありません）。
その場で「筋トレ」専用カレンダーを新しく作ることもできます。

---

## 0. 仕組みと制約

| 項目 | 内容 |
|---|---|
| 方式 | ブラウザから直接 Google カレンダーAPIを呼びます。サーバーも秘密鍵も使いません |
| 必要なもの | Google Cloud の **OAuth クライアントID**（無料・公開してよい識別子） |
| 書き込みのタイミング | **終了ボタンを押したとき**だけ。アプリを開いていないときは何も起きません |
| 認可の有効期間 | 約1時間。切れても、Googleにログインしていれば画面を出さずに取り直します |
| 連携する人 | **一人ずつ**。各自が自分のGoogleアカウントで連携し、自分のカレンダーに書きます |

---

## 1. Google Cloud でプロジェクトを作る

1. [console.cloud.google.com](https://console.cloud.google.com/) を開く
2. 上部のプロジェクト選択 → **新しいプロジェクト** → 名前は `liftlog` など → 作成

## 2. Calendar API を有効にする

1. 左メニュー **APIとサービス** → **ライブラリ**
2. `Google Calendar API` を検索して **有効にする**

## 3. OAuth 同意画面を設定する

1. **APIとサービス** → **OAuth同意画面**
2. User Type は **外部** を選んで作成
3. アプリ名（`LiftLog` など）、ユーザーサポートメール、デベロッパーの連絡先メールを入力
4. スコープの追加で、次の2つを選ぶ（検索窓に貼ると出ます）

   | スコープ | 用途 |
   |---|---|
   | `.../auth/calendar.events` | 予定の作成と削除 |
   | `.../auth/calendar.calendarlist.readonly` | カレンダー一覧の取得 |

5. **テストユーザー**に、使う人のGoogleアカウントを全員追加する

> 公開ステータスは「**テスト**」のままで構いません。テストユーザーに入っていれば使えます
> （100人まで）。この状態だと同意画面に「確認されていないアプリ」という警告が出ますが、
> 「詳細」→「安全ではないページに移動」で進めます。身内で使う分には審査は不要です。

## 4. OAuth クライアントIDを作る

1. **APIとサービス** → **認証情報** → **認証情報を作成** → **OAuth クライアント ID**
2. アプリケーションの種類: **ウェブ アプリケーション**
3. **承認済みの JavaScript 生成元** に、アプリを開くURLの**オリジンだけ**を追加

   ```
   https://aenocyon13.github.io
   ```

   > パス（`/liftlog/`）は付けません。付けると保存できません。
   > ローカルで試すなら `http://localhost:4399` も足しておきます。

4. **承認済みのリダイレクトURI** は**空のままで構いません**（この方式では使いません）
5. 作成すると「クライアントID」が出ます。`...apps.googleusercontent.com` で終わる文字列です

> **クライアントシークレットは使いません。** 控える必要も、アプリに貼る必要もありません。

## 5. Supabase にカレンダー用の列を足す

連携の前に、Supabase の SQL Editor で
[`supabase/migrations/002_google_calendar.sql`](../supabase/migrations/002_google_calendar.sql)
を1回実行してください。これを忘れると、カレンダーを選んだところで
`Could not find the 'calendar_id' column of 'profiles'` と出て保存できません。

## 6. アプリに登録して連携する

1. アプリの **設定** → **Googleカレンダー**
2. クライアントIDを貼って **保存**
3. **Googleカレンダーと連携する** → Googleの同意画面 → 許可
4. カレンダーの一覧が出るので、書き込み先を選ぶ
   （「『筋トレ』カレンダーを新しく作る」でもOK）

これで完了です。次のワークアウトから自動で入ります。

毎回貼るのが面倒なら、[`frontend/js/config.js`](../frontend/js/config.js) の `DEFAULT_GOOGLE.clientId`
に書いてコミットしても構いません。クライアントIDは公開前提の識別子です。

---

## 使っているとき

- **カレンダーを変える** … 設定 → Googleカレンダー → 「カレンダーを変更」
- **連携をやめる** … 「連携を解除」。これから先は追加されなくなります（すでにある予定は残ります）
- **記録を消す** … 月間レポートの「○月のワークアウト」から削除すると、**カレンダーの予定も一緒に消えます**
- **カレンダーへの追加に失敗した** … 記録そのものは保存済みです。メッセージのとおり設定を直してください

---

## うまくいかないとき

| 症状 | 原因と対処 |
|---|---|
| 「クライアントIDが正しくないか、承認済みのオリジンにこのサイトが入っていません」 | 手順4の **JavaScript 生成元** に `https://aenocyon13.github.io` を入れてください（パスは付けない） |
| 「ポップアップがブロックされました」 | ブラウザのポップアップ許可を出してから、もう一度「連携する」 |
| 同意画面で「このアプリは確認されていません」 | テスト中は正常です。「詳細」→「安全ではないページに移動」で進めます |
| 「Google の認証が切れました」 | 1時間ほどで切れます。設定 → Googleカレンダーから連携し直してください |
| 「カレンダーへの権限が足りません」 | 手順3のスコープ2つが入っているか確認し、連携し直してください |
| 予定が作られない | 設定で連携済みか、クライアントIDが保存されているかを確認してください |
| `Could not find the 'calendar_id' column of 'profiles'` | 手順5の SQL が未実行です。実行すれば直ります |
| アクセスをブロックされた | テストユーザーに自分のGoogleアカウントが入っていない可能性があります |
